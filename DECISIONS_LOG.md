### Решение №5: Финальный интерфейс — PyQt6 (полная пересборка)

**Дата:** 2026-09-27
**Статус:** 🟢 Принято
**Автор:** владелец проекта

**Контекст:**
Нужно, чтобы программа неотличимо выглядела и работала как покупная:
собственное окно, без терминала и браузера.

**Рассмотренные варианты:**

- PyWebView (обёртка текущего веб-интерфейса в окно) — плюс: быстро и дёшево;
  минус: внутри остаётся веб-технология, ощущение «покупной программы» неполное.
- Полная пересборка на PyQt6 — плюс: настоящее настольное приложение, полный
  контроль; минус: самый трудоёмкий путь, несколько недель работы.

**Выбрано:** Полная пересборка на PyQt6 (выбор владельца).

**Обоснование:**
ИТ-архитектор первоначально рекомендовал PyWebView как менее рискованный путь.
Владелец сознательно выбрал PyQt6 ради полного соответствия уровню покупных
программ. Архитектор поддержал выбор при условии обязательного разделения
`app.py` до начала пересборки (Решение №6) и правила стабилизации: на время
Этапа 13 новые функции не добавляются, пока PyQt-версия не достигнет паритета
со Streamlit-версией.

**Последствия:**

- Streamlit-версия остаётся рабочей до полного паритета PyQt-версии.
- Любой новый код интерфейса после Этапа 12 пишется с расчётом на перенос в PyQt.
- Выше общие трудозатраты; риск длительного периода с двумя интерфейсами
  контролируется правилом стабилизации.

### Решение №6: Разделение `app.py` по схеме «интерфейс / контроллеры / состояние»

**Дата:** 2026-09-27
**Статус:** 🟢 Принято
**Автор:** ИТ-архитектор

**Контекст:**
`app.py` — монолит на 906 строк, где смешаны интерфейс, логика операций
и состояние. Это мешает развитию и делает пересборку интерфейса крайне дорогой.

**Рассмотренные варианты:**

- Оставить как есть — минус: каждая правка рискованна; пересборка интерфейса
  потребует переписывания логики.
- Разделить на слои — плюс: логика переиспользуется в любом интерфейсе;
  минус: временное замедление разработки.

**Выбрано:** Разделение на слои:

- `astro_core/` — расчёты (уже существует, не зависит от интерфейса);
- контроллеры — логика операций (карта, транзиты, прогрессии, профили),
  без импортов Streamlit/Qt;
- слой состояния — единое управление данными сессии;
- слой интерфейса — только отображение и ввод (сейчас Streamlit, затем PyQt).

**Обоснование:**
Принципы «Разделение ответственности» и «Слабая связанность». Критерий
правильности разделения: контроллеры должны импортироваться и тестироваться
без установленного Streamlit.

**Последствия:**
Переход на PyQt6 (Этап 13) затрагивает только слой интерфейса.
Документ `ARCHITECTURE_Astroprocessor.md` будет создан на этом этапе.

### Решение №9: Использование `st.color_picker` вместо `st.color_input`

**Дата:** 2026-10-01
**Статус:** 🟢 Принято
**Автор:** ИТ-архитектор (вынужденное решение)

**Контекст:**
В шаге 2.4 для выбора цветов планет и аспектов планировался виджет
`st.color_input`. Однако в установленной версии Streamlit (1.64.0) этот
виджет отсутствует (`hasattr(st, 'color_input') == False`), хотя в
стандартных поставках он доступен с версии 1.23.0. Причина аномалии не
установлена (возможна нестандартная сборка).

**Рассмотренные варианты:**

- Переустановить/обновить Streamlit ради одного виджета — минус: риск
  побочных эффектов, не оправдан ради косметики.
- Использовать `st.color_picker` — плюс: есть во всех версиях, функционально
  эквивалентен для нашей задачи; минус: чуть менее удобный ввод hex-кода.

**Выбрано:** `st.color_picker`.

**Обоснование:**
Принцип «Надёжность и стабильность»: не меняем окружение ради некритичного
виджета. Функциональность (выбор цвета) полностью сохранена.

**Последствия:**

- Цвета планет и аспектов в интерфейсе выбираются через палитру, а не поле ввода.
- На Этапе 13 (переход на PyQt) цветовые виджеты будут реализованы средствами
  Qt, поэтому данное ограничение временное.

### Решение №10: Транзиты используют enabled_planets из профиля

**Дата:** 2026-10-04
**Статус:** 🟢 Принято
**Автор:** ИТ-архитектор

**Контекст:**
В шаге 2.5 потребовалось применить профили отображения к транзитам.
Обнаружено несоответствие контрактов: в профиле ключ называется
`enabled_planets`, а в ядре транзитов (`transits.py`) функция
`calculate_transit_positions` ищет ключ `transit_planets`.

**Рассмотренные варианты:**

- Переименовать ключ в ядре транзитов — минус: ломает обратную совместимость,
  требует правок в тестах.
- Добавить «переводчик» в UI (`app.py`) — плюс: минимальное изменение, изолировано
  в UI; минус: логика трансляции ключей размазана по коду.

**Выбрано:** Добавить трансляцию в `app.py`: перед вызовом функций транзитов
копировать `enabled_planets` в `transit_planets`.

**Обоснование:**
Принцип «Слабая связанность»: ядро транзитов не знает о профилях отображения,
UI отвечает за адаптацию контрактов. Обратная совместимость сохранена.

**Последствия:**

- Транзиты используют только планеты из профиля натальной карты.
- Если в будущем ключи будут унифицированы, трансляцию можно убрать.

### Решение №11: Исправление невидимых символов на натальной карте

**Дата:** 2026-10-06
**Статус:** 🟢 Принято
**Автор:** ИТ-архитектор

**Контекст:**
При отображении натальной карты символы планет, астероидов и узлов не отображались (были невидимы). SVG содержал символы Юникода, но они рисовались белым цветом на белом фоне. Видимы были только Сатурн (♄) и Плутон (♇) — их тёмный цвет точек срабатывал в ветку с тёмным текстом.

**Рассмотренные варианты:**

- Использовать единый тёмный цвет для всех подписей — плюс: просто; минус: теряется цветовая кодировка планет.
- Совместить логику с транзитной картой — плюс: единообразие, цветовая кодировка сохраняется; минус: нужно аккуратно перенести список «тёмных» цветов.

**Выбрано:** Совместить с логикой транзитной карты (подписи используют цвет планеты, для очень тёмных — чёрный).

**Обоснование:**
Транзитная карта (`chart_svg.py:736`) уже работала правильно. Натальная карта имела баг в ветке `else "#ffffff"`. Исправление делает поведение единообразным и сохраняет цветовую кодировку, полезную для чтения карты.

**Последствия:**

- Все 13 символов (10 планет + Хирон + 2 узла) теперь видны на натальной карте.
- Переключатели видимости подписей работают корректно.
- Транзитная карта не затронута (уже была правильной).
- Все 126 тестов проходят.
